# 撮影直後のサムネイル待ち受け

## 概要・やりたいこと
今はサムネイルのショートカット（Esc / ⌘C / ⌘S / ⌘O / ⌘E / ⌘P）がホバー中しか効かないので、撮るたびにマウスをサムネイルまで動かしている。撮影の直後だけ、マウスを動かさなくても最新のサムネイルがキーを受ける「待ち受け」状態にして、撮る → ⌘C → 貼る、の流れを速くする。

ただし待ち受け中は前面アプリの ⌘C / Esc / ⌘S 等を横取りする（Carbon のグローバルホットキーなので）。事故を防ぐため、ユーザーが別の操作を始めた合図で待ち受けを解く。

## 前提・わかっていること
- 現状: `ThumbnailView.setHovered` がホバー中だけ `registerHoverKeys()` でキーを登録し、外れたら解除する（`Sources/App/Thumbnail/ThumbnailPanel.swift`）。パネルは `canBecomeKey = false` で本当のフォーカスは取らない。この方式は変えない（アクセシビリティ許可を要らなくするため）
- サムネイルは自動では消えない（最大 5 枚）ので、時間制限なしでキーを持たせると横取りが常態化する → 却下
- 撮影後にマウスカーソルをサムネイルへ動かす案（`CGWarpMouseCursorPosition`）は、カーソルが飛ぶのが不快・2 画面で画面をまたぐので却下
- 操作仕様

  | 項目 | 仕様 |
  |---|---|
  | 待ち受けに入る | 最新のサムネイルが出たとき: 撮影（静止画 `CaptureService` / 録画 `recorder.onSaved`）、キャプチャ履歴の Restore、編集の保存による差し替え（`replace`） |
  | 対象 | 直前に出した／差し替えた 1 枚だけ（`replace` は index > 0 もありうる）。新しく待ち受けに入ったら前の待ち受けは解く |
  | キーの持ち主 | サムネイルのキーを持つのは常に 1 枚だけ（Carbon の同じ組み合わせを二重登録すると失敗 or 両方走る）。持ち主は controller が管理し、待ち受けに入る前に他のサムネイルのホバーのキーを手放させ、その表示も消す（次の mouseEntered で取り直す）。待ち受け中に別のサムネイルへホバーしたら、先に待ち受けを解いて（`reason=hover_other`）からそちらが取る |
  | 見た目 | 枠を光らせる程度にとどめ、画像は隠さない（撮った中身を確かめたいのはこの瞬間なので）。ぼかし＋ボタンはホバー時だけ |
  | 効くキー | ホバー時と同じ（動画は Esc / ⌘S だけ） |
  | 解除: クリック | どこかをマウスでクリックした（左・右・その他のボタン）（他アプリ: `NSEvent.addGlobalMonitorForEvents`、自アプリの別ウィンドウ: local monitor）。**待ち受け中のサムネイル自身へのクリックは解除しない**（ボタンを押す・ドラッグで持ち出すため） |
  | 解除: アプリ切り替え | 前面アプリが変わった（`NSWorkspace.didActivateApplicationNotification`） |
  | 解除: 時間 | 5 秒（仮。使ってみて調整）。同じアプリでキーボードだけで作業に戻るケースは許可なしでは検出できないので時間で区切る |
  | 解除: 次の撮影 | 新しい最新に待ち受けが移る |
  | マウス移動 | **解除しない**（手が触れて少し動くのは普通なので） |
  | ホバーとの関係 | 待ち受け中にホバーしたら、キーを残したまま待ち受けを終えて通常のホバーに引き継ぐ（`reason=hover`。タイマー・監視も外す）。そこから外に出たら今までどおりホバーの解除 |
  | 解除: 自アプリの操作 | 編集を開く（`reason=edit`）・キャプチャ履歴を開く（`reason=history`）・録画を始める（`reason=record`。カウントダウンの Esc と衝突するため）。Carbon のキーは自アプリのウィンドウより先に取るので、残すと編集の ⌘S が「Downloads へ保存」に化ける |
  | 編集ウィンドウが開いている | 待ち受けに入るがキーは取らない（`editor_open=true keys=0`）。編集の ⌘S を横取りしないため |
  | 閉じる・差し替え | そのサムネイルが閉じたら待ち受けも解く（`releaseKeys` の経路で） |

- 罠: Restore / 編集の保存は `activate()` で前のアプリに戻してからサムネイルを出す。撮影も OS の選択 UI から前面が戻るかもしれない。その通知で即解除されないよう、待ち受けには「戻る先のアプリ」を渡し、そのアプリの activate は無視する（撮影: 撮り始めの前面アプリ / Restore・編集: 開く前の `previousApp` / 録画: フォーカスが動かないので `nil` ＝どのアプリの activate でも解除）。`previousApp` はコールバックの時点で `close` により消えているので、消す前に取ってコールバックの引数で渡す。時間の猶予で逃げる案は通知の遅れ次第で漏れるので採らない
- 撮影の瞬間は `setHidden(true)` で隠している。待ち受けは再表示（`setHidden(false)`）後に始まる順序にする
- 検証は検証フック（dev 版のみ）とログで行う。実際に撮る確認はユーザーが自分の Terminal で行う（CLAUDE.md の会社貸与 PC の制約）。検証で `NSPasteboard` に書かない
