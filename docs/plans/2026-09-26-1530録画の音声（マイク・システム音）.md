# 録画の音声（マイク・システム音）

## 概要・やりたいこと
今の動画録画（オールインワン ⌘⇧5 の Recording）は音声なし（`Recorder.swift` の `config.capturesAudio = false`）。
録画の前に次の 2 つを ON/OFF できるようにする。
- マイク
- システム音（Mac から出る音）

CleanShot X の録画で使っていた機能の置き換え。

## 前提・わかっていること
- deployment target は macOS 26。SCStreamConfiguration の `capturesAudio`（システム音）と `captureMicrophone`（マイク）で両方録れる。今と同じく SCRecordingOutput に書く
- システム音は今の画面収録の許可だけで録れる。mycap 自身の音（録画サムネイルのプレビュー等）は `excludesCurrentProcessAudio = true` で外す
- マイクには次が要る
  - Info.plist に `NSMicrophoneUsageDescription`
  - `mycap.entitlements` に `com.apple.security.device.audio-input`（Hardened Runtime が有効なので、これが無いとマイクは黙って無音になる。make-release-zip.sh の再署名も同じファイルを使うので、足すのはここだけ）
  - マイクの許可（TCC）。初回は `AVCaptureDevice.requestAccess(for: .audio)` で OS のダイアログを出す
- マイクはシステムの既定の入力デバイスを使う。デバイスを選ぶ UI は作らない
- **決定: 切り替えの UI** — オールインワンのツールバーで、Recording の横にマイクとスピーカーのトグルを置く。状態は UserDefaults に残す（再起動・更新をまたぐ。初期値は両方 OFF）。録画中は切り替えられない（開始時に固定）。設定画面は作らない方針は変えない（トグルは撮影 UI の一部）
- **決定: 両方 ON のときの音声トラック** — 停止後に音声を 1 トラックへ混ぜて書き直す。映像はパススルー（再エンコードしない）。ブラウザ・Slack のプレビューは 1 本目の音声トラックしか鳴らさないことが多いため。混ぜている間はサムネイルが出るまで少し待つ
  - SCRecordingOutput がマイクとシステム音を別トラックに書くというのは見込み。Phase 1 で実物の mp4 を見て確かめる。最初から 1 本で書かれるなら、混ぜる処理（Phase 3）は要らない
- マイクが ON で許可が無い・拒否されたとき: トーストで知らせて、マイクなしで録る（録画自体は止めない）
- 録画サムネイルの 🔊 表示（`ThumbnailController` の `hasAudio`）は今のまま効く
- 会社貸与 PC ではセッションからのビルドが ad-hoc 署名になるので、実際に録る確認（画面収録・マイクの許可が要る）はユーザーが自分の Terminal の `mise run run` で行う

## 実装計画

### Phase 1: 録音の経路と実物の確認 [AI🤖]
- [ ] `RecordingAudio`（mic / system の Bool）を UserDefaults で持つ型を足す（`LastRegion.swift` と同じ書き方）
- [ ] `Recorder.start(with:)` で `capturesAudio` / `captureMicrophone` / `excludesCurrentProcessAudio` を設定する。`record.started` のログに `mic= system=` を足す
- [ ] マイク ON のときは開始前に `AVCaptureDevice.authorizationStatus(for: .audio)` を見る。未決定なら `requestAccess` を出し、拒否ならトーストを出してマイクなしで続ける（`record.mic_denied` をログに出す）
- [ ] Info.plist に `NSMicrophoneUsageDescription`、`mycap.entitlements` に `com.apple.security.device.audio-input` を足す
- [ ] 検証フック `--aio-record` / `--record-display` に音声の指定（例 `--audio mic,system`）を足す
- [ ] 両方 ON で録った mp4 の音声トラックの本数を `afinfo` / AVAsset で数えて、ログ > 試したこと に書く

### Phase 2: ツールバーのトグル [AI🤖]
- [ ] `AIOToolbar` の Recording の右にマイク（`mic` / `mic.slash`）とスピーカー（`speaker.wave.2` / `speaker.slash`）のトグルを置く。今の見た目（ダークガラス・`AIOToolButton` の大きさ）に揃える
- [ ] `AIOModel` にトグルの状態を持たせ、変えたら UserDefaults に書く。`aio.audio_toggled kind= on=` をログに出す
- [ ] 暗幕が `.nonactivatingPanel` のままクリックでトグルが効くことを確かめる（Capture 等のボタンと同じ経路）
- [ ] ツールバーのスナップショットの検証フックがあれば、トグルの ON/OFF 両方で撮って見る

### Phase 3前の判断 [AI🤖]
- [ ] Phase 1 の結果、音声トラックが 1 本ならこの Phase を取り消し線にして、ログ > 方針変更 に理由を書く

### Phase 3: 停止後に音声を 1 トラックへ混ぜる [AI🤖]
- [ ] 音声トラックが 2 本以上あるときだけ、AVAssetReader / AVAssetWriter で映像はパススルー、音声は 2 本を混ぜた AAC 1 本にして書き直す（AVAudioMix か、読み出した PCM を足し合わせる）。1 本以下なら何もしない
- [ ] `Recorder.finishRecording` で `CaptureStore.keep` の前に挟む。失敗したら元の 2 トラックの mp4 をそのまま置く（録画を失わない）。`record.audio_mixed tracks= ms=` / `record.audio_mix_failed` をログに出す
- [ ] 純粋関数に切り出せる部分（トラック本数から混ぜるかどうかの判定など）は `Sources/Core` に置いてテストする
- [ ] 長めの録画（数分）で混ぜる時間を測って、ログに書く

### Phase 4: 仕上げ [AI🤖]
- [ ] CLAUDE.md の「固定の挙動」の録画の項に、音声のトグルとトラックの扱いを足す
- [ ] VERIFY.md に音声付き録画の検証フックとログを足す
- [ ] docs/CHANGELOG.md の Unreleased に書く

### 動作確認 [人間👨‍💻]
- [ ] 自分の Terminal で `mise run run` → ⌘⇧5 でマイクを ON → Recording。初回はマイクの許可ダイアログが出ること
- [ ] マイクだけ／システム音だけ／両方／両方 OFF で録り、それぞれ期待どおりの音が入ること（システム音は YouTube 等を流す）
- [ ] 両方 ON の mp4 を Slack かブラウザに貼って、マイクとシステム音の両方が鳴ること
- [ ] mycap を再起動してもトグルの状態が残っていること
- [ ] 録画サムネイルに 🔊 が出て、プレビュー（Space）・トリム（⌘E）でも音が出ること
