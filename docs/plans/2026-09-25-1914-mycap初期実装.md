# mycap 初期実装（CleanShot X 代替の自分用スクリーンショットアプリ）

## 概要・やりたいこと

CleanShot X のうち実際に使う機能だけを持つ、自分用の Mac アプリ `mycap` を作り、CleanShot X を置き換える。

v1 に入れるもの:
- 範囲・ウィンドウ・全画面のキャプチャ → クリップボードへのコピー＋`~/Downloads` への保存
- グローバルホットキー（CleanShot で使っていた ⌘⇧ 系を引き継ぐ）
- OCR（Vision、日本語＋英語）
- ピン留め（最前面に浮かぶ画像パネル）
- 撮影直後に画面の隅へ出るサムネイル（ドラッグで持ち出せる）
- 動画録画（mp4、ScreenCaptureKit）
- デスクトップアイコンを隠す・背景と余白を付ける整形

v1 に入れないもの: 注釈エディタ（v2 で「描いたら確定」の簡易版から）、範囲選択 UI の自作、範囲を指定した録画、スクロールキャプチャ、GIF、クリック位置の強調、音声の同時録音、録画のトリム、整形の比率固定と自動適用。

兄弟アプリ `~/mycast`（Raycast 代替。2026-09-24 作成）と同じ型で作る。挙動は**固定値**としてコードに焼き込み、設定画面は作らない。

## 前提・わかっていること

### 技術・配布（mycast の構成を流用）
- Swift + AppKit（パネルの中身は SwiftUI 可）+ XcodeGen。`project.yml` が真実の源で、`.xcodeproj` は生成物。`deploymentTarget` は macOS 26.0（手元は 26.6.2）
- コピー元は `~/mycast` の `project.yml`・`.mise.toml`・`scripts/`（ensure-signing-xcconfig / gen-signing-xcconfig / install-app / make_icon.swift / make-release-zip / notarize / preflight / release / changelog.py）・`Sources/App/HotKeys.swift`（Carbon の `RegisterEventHotKey`。アクセシビリティ許可は要らない）・`Sources/Core` と `mycastTests` のテスト構成（テストはアプリをホストにせず、純粋関数だけをコンパイルする）
- 作法は `~/Library/CloudStorage/Dropbox/dotfiles/.claude/references/personal-mac-apps.md` と `swift-projects.md` に従う（dev/常用の分離、バージョンの一元管理、`docs/CHANGELOG.md` の `[Unreleased]` ゲート、dev 版に `SUFeedURL` を入れない等）
- bundle id は常用が `io.github.nyshk97.mycap`、dev が `io.github.nyshk97.mycap.dev`。表示名は `mycap` / `mycap Dev`。dev はアイコンに DEV リボンを付ける
- 配信は mycast と同じ形にする。本体 repo `nyshk97/mycap`（public）の GitHub Release に置き、feed は `https://github.com/nyshk97/mycap/releases/latest/download/appcast.xml`、cask は `nyshk97/tap/mycap`。Sparkle の EdDSA 鍵は `--account mycap` で作る
- 外部ライブラリは Sparkle だけにする。KeyboardShortcuts は入れない
- **開発機は会社貸与 PC（`TsubasanoMacBook-Pro`）**。セッションからは keychain に触る操作を実行しない（`security find-identity`・証明書での `codesign`・`generate_keys`・`sign_update`・notarize・`mise run release`）。セッションの検証ビルドは、署名 xcconfig が無ければ ad-hoc 署名になる。`mise run signing`・Sparkle 鍵の作成・リリースはユーザーが自分の Terminal で叩く
- 署名は mycast と同じく、dev 版も常用版と同じ Developer ID Application で行い、`/Applications/mycap Dev.app` の固定パスに置いて動かす（Apple Development 証明書は更新時に CN が変わり、TCC の許可が外れうるため。mycast で決めた方式）

### 常駐・メニューバー
- Dock には出さない（`LSUIElement`）。常用版だけログイン時に自動起動する（`SMAppService.mainApp.register()`）。Sparkle の自動チェックは ON（常駐して存在を忘れる種類のアプリのため）
- シングルインスタンスにする。dev と常用は bundle id が別なので同時に起動できる
- メニューバーのメニュー: 範囲／ウィンドウ・全画面・OCR・録画の開始（各項目にホットキーを併記）／デスクトップアイコンを隠す（トグル）／サムネイルを全部閉じる／About・バージョン `v0.x.y`／アップデートを確認／終了
- 録画中はメニューバーのアイコンを赤い● と経過時間（`● 0:12`）に変え、クリックで停止する
- ログは `~/Library/Logs/mycap/mycap.log`（dev は `mycap-dev.log`）。イベント名は固定文字列にする（`capture.region.saved`、`tcc.preflight` 等）

### ホットキー（固定。Carbon の `RegisterEventHotKey`）
| 操作 | 常用版 | dev 版 |
|---|---|---|
| OCR | ⌘⇧2 | ⌃⌥⌘2 |
| 全画面 | ⌘⇧3 | ⌃⌥⌘3 |
| 範囲／ウィンドウ | ⌘⇧4 | ⌃⌥⌘4 |
| 録画の開始／停止 | ⌘⇧5 | ⌃⌥⌘5 |

- OS 標準のスクショショートカット（symbolichotkeys 28〜31・184）は、すでに全部オフになっている（2026-09-25 に実機で確認）。OS 側との衝突は無い
- 常用版は CleanShot X と同じキーを取り合う。登録に失敗したら、mycast と同じく起動時に NSAlert で知らせ、以後はメニューバーのアイコン表示で気づけるようにする。加えて、常用版は起動時に CleanShot X（`pl.maketheweb.cleanshotx`）が動いていたらメニューバーで警告する

### キャプチャ（静止画）
- `screencapture` を `Process` で呼ぶ。範囲選択 UI は OS 標準のものを使い、自作しない
  - 範囲／ウィンドウ: `screencapture -i -x <tmp>.png`（Space で範囲とウィンドウを切り替え。ウィンドウは OS 既定どおり影付き）
  - 全画面: `screencapture -x -D <n> <tmp>.png`。撮るのはマウスのあるディスプレイ。`-D` の番号と `NSScreen` の対応はマルチディスプレイの実機で確かめる
  - ファイルができなければキャンセルとみなし、何もしない（ログだけ残す）
- 撮れたら、クリップボードへのコピーと `~/Downloads` への保存を両方やる
- ファイル名は `YYYY-MM-DD_HH-mm-ss.png`。同じ秒に同名のファイルがあれば `_2`、`_3` … を付ける（純関数にしてテストする）
- `screencapture` は撮った座標を返さないので、「撮った位置にそのままピン留めする」はできない

### 撮影後のサムネイル
- 撮った画面（撮影時にマウスがあったディスプレイ）の右下に出し、複数枚あれば上へ積む。閉じるまで自動では消えない
- 最大 5 枚。6 枚目を撮ったら一番古いものを閉じる（ファイルは `~/Downloads` に残る）。内蔵 1 枚（高さ 982pt）でも 5 枚が収まる大きさにする
- ホバーで出すボタン: コピー・ピン留め・OCR・整形・Finder で表示・削除（ゴミ箱へ移す）・閉じる。ホバー中の 1 枚は Esc で閉じる
- ドラッグで持ち出せる（ファイル URL を渡す）。持ち出したら閉じる
- 録画のサムネイルには動画の先頭フレームを使う。ボタンは Finder で表示・削除・閉じるだけ（ドラッグで持ち出せる）
- パネルは `.canJoinAllSpaces` ＋ `.fullScreenAuxiliary`（`.moveToActiveSpace` と同時に指定すると例外になる）。表示位置は `NSScreen.main` を使わず、マウス位置から `NSScreen.screens` を引いて決める
- ディスプレイをつないだり外したりして、サムネイルの画面が無くなったら、残っている画面へ積み直す

### OCR
- ⌘⇧2 → `screencapture -i -x` で範囲を選ぶ → Vision の `VNRecognizeTextRequest`（`recognitionLanguages = ["ja-JP", "en-US"]`、`.accurate`、言語補正あり）→ 改行を残したテキストをクリップボードに入れ、冒頭をトーストで表示する
- この経路では画像を保存せず、サムネイルも出さない。文字が見つからなければ、そうトーストで伝える
- サムネイルとピンからも同じ OCR を呼べる（処理は共通にする）

### ピン留め
- マウスのある画面の中央に実寸で出す。画面より大きければ、収まるまで縮小する
- 影付き。全 Space とフルスクリーンの上にも浮かぶ（level は `.floating` 以上）
- ドラッグで移動、スクロールかピンチで拡大縮小、⌘C でコピー、Esc かダブルクリックで閉じる。右クリックで「コピー・OCR・透明度・閉じる」
- 複数枚を同時に出せる

### 動画録画
- ⌘⇧5 → OS 標準の `SCContentSharingPicker` でディスプレイかウィンドウを選ぶ → 画面中央に 3 秒のカウントダウン（Esc か ⌘⇧5 でキャンセル）→ `SCRecordingOutput` で mp4 に書く
- 形式は論理解像度（1x。Studio Display なら 2560×1440、内蔵なら 1512×982）・H.264・30fps。カーソルは写す。H.264 は幅 4096 を超えられないので、2x は使わない
- mycap 自身のウィンドウ（カウントダウン・サムネイル・ピン）は `SCContentFilter` で録画から外す。デスクトップアイコンを隠すトグルがオンなら、Finder のデスクトップのウィンドウも外す
- 録画中は、メニューバーの赤い● のクリックか ⌘⇧5 で止める。画面に浮かぶ停止ボタンは出さない（録画に写り込むため）
- 止めたら `~/Downloads/YYYY-MM-DD_HH-mm-ss.mp4` に保存し、動画のサムネイルを出す。クリップボードには載せない
- 録画中に対象のウィンドウが閉じられるなどして SCK が止まったら、そこまでのファイルを保存し、トーストで知らせる

### デスクトップアイコン隠し
- メニューバーのトグルでオン／オフする。オンの間は、デスクトップアイコンより上・通常のウィンドウより下の層（`kCGDesktopIconWindowLevel + 1`）に、壁紙を表示したウィンドウを各ディスプレイへ敷く
- 壁紙は `NSWorkspace.shared.desktopImageURL(for:)` から読む。静止画として読めない（動く壁紙など）ときは単色で塗る
- ディスプレイをつないだり外したりしたら（`NSApplication.didChangeScreenParametersNotification`）敷き直す
- オンかどうかは UserDefaults に覚えておき、再起動後も同じ状態に戻す
- Finder の `CreateDesktop` を書き換える方式は採らない（Finder が再起動し、開いているウィンドウが一瞬消えるため）

### 背景と余白の整形
- サムネイルの「整形」で、プレビュー付きの小さなパネルを開く
- 選べるのは、背景（グラデーション 4 種＋単色＋透明）・余白（スライダー）・角丸・影だけ。前回の設定を UserDefaults に覚えておく
- Enter（または確定ボタン）で `<元の名前>_styled.png` を `~/Downloads` に保存してコピーし、その画像のサムネイルを出す。元の画像は残す
- 描画は Core Graphics の純関数に寄せる（入力画像＋設定 → 出力画像。出力サイズの計算はテストする）

### 画面収録の権限（TCC）
- 静止画でも画面収録の許可が要る（TCC は `screencapture` を呼び出したアプリを権限の持ち主として見る。swift-projects.md の記述）。これを Phase 1 で実機検証する
- `SCContentSharingPicker` 経由の録画に画面収録の許可が要るかどうかは未確認。Phase 1 で実機検証する
- Tahoe で許可の再確認が実際どのくらいの頻度で出るかは、キャプチャのたびに `CGPreflightScreenCaptureAccess()` の結果をログに残し、数週間の実測で答える
- 許可が無いときは `CGRequestScreenCaptureAccess()` で OS のダイアログを出し、システム設定の該当ページを開く導線をトーストに置く

### 動作確認できる作り（dev 版だけの起動引数フック。実機能と同じ経路を通す）
- `--ingest <png>`: `screencapture` の代わりに既存の画像を撮影結果として受け取り、以降の処理（保存・サムネイル）を同じ経路で流す
  - ただし、この経路ではクリップボードに書かない。検証でユーザーのクリップボードを上書きしないため
- `--ocr <png>`: OCR の結果を stdout とログに出す（クリップボードには書かない）
- `--pin <png>` / `--style <png> --style-out <png>`: ピンを出す／整形結果を書き出す
- `--snapshot <png>`: サムネイル・ピン・整形パネルをプロセス内で描画して保存する（画面収録の許可は要らない）
- 保存先を差し替える環境変数 `MYCAP_SAVE_DIR`（dev 版のみ）。検証で `~/Downloads` を汚さないため
